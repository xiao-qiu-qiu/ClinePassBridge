# 套餐用量

在「配置概览 → 凭据与套餐用量」查看 Cline 账号的套餐名称、当前订阅周期，以及 5 小时、每周、每月的已用百分比和重置时间。时间按浏览器本地时区显示，百分比使用 Cline 返回值；缺失值显示 `—`，不当作零用量。

凭据按名称排序，每页 12 个，可搜索名称或 ID。支持单个刷新和刷新本页。插件后台按账号约每分钟查询用量，不依赖页面、分页或浏览器是否打开。同账号多个 Key 完成身份识别后合并查询并共享最新用量，不同账号独立采样。最多同时查询 3 个凭据，常规结果缓存 60 秒，手动刷新保留 10 秒最小间隔，套餐名称和周期缓存 5 分钟；后台遇到鉴权失败或限流时退避 5 分钟。账号较多或上游变慢时采样间隔可能延长。

查询失败保留上次成功数据并显示时间、过期状态和原因；首次失败显示未知，不显示为 0%。更换 API Key 后旧缓存失效，旧请求的结果也不会覆盖新 Key。手动停用和额度暂停不阻止用量查询，查询保留人工启停状态。用量查询不会参与模型推理、凭据轮转或冷却。

这是账号整体套餐用量，包含账号在其他客户端的使用。同一账号的多个 Key 可能共享同一套餐，请勿累加额度。用量重置时间与订阅周期截止时间分别取自各自接口，不混用。下方的「额度估计」是插件独立计算的参考值，不是 Cline 返回的余额。

## CPA 标准配额接口

插件通过 CPA JSON ABI 声明 `quota_provider` 能力，并提供 `quota.identifier`、`quota.describe`、`quota.fetch` 和 `quota.reset`。CPA 据此在插件及凭据列表中生成 `supports_quota: true` 和 `quota_provider: "cline-pass"`；无需在插件管理页面中额外拉取私有接口。

外部管理客户端可以调用 `POST /v8/management/plugins/clinepassbridge/quota`，请求体为 `{"auth_index":"<auth_index>"}`。`auth_index` 取自 CPA 凭据列表，由 CPA 解析到对应账号；插件不会回退到其他账号。相应 GET 路由支持 `?auth_index=<auth_index>`。

响应使用 CPA 标准的 `subscription` 和 `groups[].buckets[]`：`five_hour` 转为 `window: "5h"`，`weekly` 转为 `window: "7d"`，`monthly` 保留日历月含义；`remainingFraction` 为 0–1 的剩余比例，`resetTime` 使用上游重置时间。缺失百分比的窗口不生成额度条，不推断为零用量或额度耗尽。标准接口只输出套餐显示名称和已报告窗口，不输出 API Key、账号/订阅标识或插件估算金额。

标准接口复用插件页面及后台采样的缓存、查询合并、代理和额度保护逻辑，主动查询保留 10 秒最小间隔。手动停用及额度暂停的账号仍可查询。上游查询失败时标准接口返回错误，避免把旧数据作为当前配额；插件自身页面仍保留旧值和过期提示。套餐信息单独查询失败时可返回有效窗口，但不附带过期套餐名称。

上游不提供额度重置操作，`quota.describe` 声明 `supports_reset: false`，`quota.reset` 返回 `success: false`，不清除 CPA 冷却、不修改账号启停状态或额度保护。该接口按 [CPA 标准配额契约](https://github.com/router-for-me/CLIProxyAPI/blob/v8.0.31/sdk/pluginapi/types.go)对接，已在原版 CPA v8.0.31、v8.0.32 的配额路由验证。

## 额度估计

每个时段的用量条下方以紧凑一行展示单个估计总额度，单位为按官网价格折算的 USD；悬停金额可查看预计剩余、误差与采样来源说明；卡片不常驻显示备注。点击「采样依据与计价说明」查看总额度的代入计算式，实际数值加下划线，结果与卡片一致；悬停计算式查看样本段数、请求数、token 数及采样时间。弹窗随卡片同步更新。

按全部额度消费均由 CPA 本插件记录的假设估计，不额外扩展金额区间。5 小时与每周分别采样；月总额度固定取同账号周估值的两倍，无需等待月百分比变化。月百分比仍来自 Cline，月剩余额度用月总额度与实际月百分比计算。周估值尚未形成时，月估值等待周采样；周初步/历史状态同步到月估值。

首次成功查询套餐建立基线。之后每次刷新用量，将该账号在两次有效采样之间的请求折算消费与已用百分比变化配对：

```text
请求参考消费 = (普通输入 × 输入价 + 缓存读取 × 读取价
               + 缓存写入 × 写入价 + 输出 × 输出价) / 1,000,000
5 小时/周估计总额度 = 样本参考消费 / (已用百分比变化 / 100)
月估计总额度 = 周估计总额度 × 2
估计剩余 = 估计总额度 × (1 - 最新已用百分比 / 100)
```

- 普通输入从总输入中扣除缓存读取和写入；推理 token 已包含在输出中，不重复计费。按**实际上游模型 ID**匹配价格，客户端别名不影响计价。
- 价格快照来自 [Cline 官网](https://docs.cline.bot/getting-started/clinepass#reference-pricing)，核对日期 **2026-11-02**，完整表及依据见 [ClinePass 参考价格](clinepass-pricing.md)。DeepSeek V4.1 Flash（含 1017）和 V4 Pro 按已核实的峰谷时段折算：北京时间周一至周五 **09:00–12:00、14:00–18:00** 为峰时，中国公众假期除外；其余时间、周末和公众假期全天为谷时，谷价为峰价的一半。时间来自 Cline 价格表引用的 DeepSeek 官方规则，用于参考消费估算。
- 请求完整处于同一已知档位时采用该档；跨时段、缺少请求时间或尚未收录公众假期的年份在可能的峰时保留两档成本，单值估算取均值。插件按国务院 **2026 年**放假调休公告范围估算假期；周末即使调休上班仍按谷时规则。Kimi K3 / K3.1 Pro 的缓存写入分别有 5 分钟和 1 小时两档，当前只有写入总量、没有有效期细分时保留两档成本并取均值。Qwen 和 Kimi 必须明确返回缓存写入数（包括零），否则该请求记为用量不完整。
- Qwen3.7 Plus 以 **262,144** 输入 token 为分档阈值；MiniMax M3 以 **524,288** 输入 token 为阈值，超出后该请求的输入、输出、缓存读取价格均翻倍。阈值按总输入计算，包含缓存读写。
- 官网尚未列价的模型或未登记的相似 ID 不沿用近似型号价格；MiMo V2.6 Pro / Flash 已按其独立价格收录，MiMo V2.5 两个旧 ID 保留最后已知价格。缺少完整 token 用量、未知价格、失败或重试的请求会增加不完整请求计数，**保留同段已知消费，不再废弃整段采样**。单次请求失败前若已返回可计价 usage，也保留该已知部分。金额统一显示 `≈`，不完整片段的原因通过悬停查看；缺失消费可能使结果偏低，不当作零消费或完整账单。
- 百分比未变化时持续积累请求。累计增加 **1 个百分点**先显示初步估计，金额旁有小黄色感叹号，悬停提示样本较少、数据可能不准；此时按参考消费除以已用比例变化计算，金额为单值，不展开取整或峰谷价格范围。初步快照不推进基线、不重复计入已接受样本。累计达到 **2 个百分点**后对完整片段校准，移除初步标记。多个有效片段按消费与比例变化求和计算，不简单平均结果；校准后仍直接按参考消费与比例变化求单值，不再使用每段 ±1 个百分点扩张区间。百分比取整及上游结算延迟仍可能影响准确性。
- 使用官方套餐响应的 `userId` 确认账号，后台只保存其哈希；备注相同也不会归并。已识别为同账号的多个 Key 合并请求计数，显示共享凭据数量。同账号新增 Key 首次归并时只重建下一段基线，保留已接受估值。实际周期重置或比例下降时，新周期单独采样，继续显示上次有效估值与其历史采样数；新周期形成有效样本后自动替换。已有校准后的历史估值时优先沿用它，不以新周期的初步值替换；只有初步估值时也会跨周期及重启保留，直到后续校准。即使连续多个周期没有请求，或页面、插件重启，也保留最后一次有效估值。5 小时与每周分别保留，月估值跟随周估值变化，不跨账号或套餐变更沿用；过期用量只显示总额度，不冒充当前剩余额度。Cline 返回的重置时间存在小幅抖动，原窗口锚点前后 2 秒以内视为同一周期，采样与展示使用相同规则；容差不随刷新累计漂移。
- 查询期间同账号有请求在进行或开始/完成时仍记录基线和消费；若片段任一端存在该并发边界，结果的悬停提示注明并发边界。百分比结算与请求完成的时间差可能使金额偏高或偏低。单值仍是估算，缺失用量、并发边界及上游延迟的影响通过悬停提示查看。5 小时为滚动窗口，旧消费过期可能抵消新消费，因此该档仅作参考；跨度超过 5 小时的片段会被排除。
- 达到 100% 后跳过可能截断的增量。无插件请求却发现额度增加时重新采样。计算假设消费均经过 CPA 本插件；未被插件记录的消费仍可能使结果偏低。
- 请求累计与采样存储在数据目录的 `estimates.json`，独立于请求日志保留条数。文件只含哈希标识、计数和用量采样，不保存 API Key 或原始账号 ID。重启保留已有样本，但重新建立下一段基线，不跨重启缺口计算；旧版日志不按备注回填。
- 本次价格修订更新估算存档的价格版本，旧价格版本的估值会重新开始采样，避免混用新旧计价规则。

插件启动后自动识别具有有效 API key 的凭据并采样，手动停用和额度暂停账号也继续查询用量；查询结果保留人工启停状态。关闭页面后持续累计请求和校准百分比，无需逐页打开。用量查询只调用官方套餐 GET 接口，不发送模型测试消息或消耗推理 tokens。插件关闭/热卸载时停止采样并关闭查询流。历史上已经丢弃的片段不凭备注或残缺日志回填；升级后等待新的额度变化形成样本。

## 接口与兼容性

- 插件管理接口：`GET /v0/management/clinepassbridge/credentials/usage?id=<凭据ID>`，手动刷新可加 `refresh=1`，由 CPA 管理鉴权保护。
- 官方来源：`GET https://api.cline.bot/api/v1/users/me/plan/usage-limits` 和 `GET https://api.cline.bot/api/v1/users/me/plan`。使用现有凭据的 Bearer API Key；Key、上游账号 ID、订阅 ID 不返回前端，用量缓存仅保留在内存。
- 上游鉴权失败、限流、超时等以该凭据的查询状态返回，不会误触发 CPA 管理密钥登录弹窗。
- 官网接口尚未确认有公开稳定性保证。未知用量窗口仍显示，缺字段或接口异常显示提示。
- 代理池关闭且凭据未指定独立代理时，用量查询使用 CPA 的宿主 HTTP 回调和全局代理。启用代理池或凭据配置了 `proxy_url` 时，查询通过插件传输，独立代理优先；代理连接失败会显示查询错误，不会绕过指定代理直连。查询也计入相应出口组的请求和并发预算。

## 测试包

普通分支推送只触发 GitHub Actions 构建。可以在对应提交的 workflow run 中下载 `package-linux-amd64` 等平台产物进行测试；正式市场安装仍取已有 Release。测试阶段不创建版本 tag 或 Release。

建议验收：检查实际账号的三档用量；添加多账号后检查搜索、翻页和单独刷新；编辑 Key 后确认数据随之更新；切换 CPA 明暗主题和窄屏检查布局。
