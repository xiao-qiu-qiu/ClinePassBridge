# 进阶配置

第一次使用请先看 [README](../README.md)。这里介绍日常使用之外的设置和接口。

## 登录与数据保存

管理页可以沿用同源 CPA / CPAMP 通过「记住密码」保存的登录信息。管理中心跨域或没有保存登录信息时，输入当前入口的管理密钥：直连 CPA 使用 CPA 管理密钥，经 CPAMP 完整模式访问则使用该面板的管理密钥。

兼容 CPA 管理前端 v1.27.0 的新登录存储格式，也保留旧版 CPA 和 CPAMP 的读取方式。该版管理前端升级时会清除旧登录记录，需要先在管理中心重新登录并勾选「记住密码」，插件才能自动复用。具体变更见[上游登录存储更新](https://github.com/router-for-me/Cli-Proxy-API-Management-Center/commit/1650cf2f726685da188237eda9e5345d0bd15354)。

支持通过子目录反向代理访问：例如管理页位于 `/my-cpa/v0/resource/plugins/clinepassbridge/console` 时，管理请求会自动使用 `/my-cpa/v0/management/clinepassbridge/`。多级子目录同样适用，保存的管理密钥也按当前子目录隔离。

手动输入的密钥通过验证后才会保存，默认保留到标签页会话结束。勾选「在此浏览器记住管理密钥」后保存在当前站点的 `localStorage`，按服务地址和代理路径区分。「清除密钥」或收到 401 时会删除插件保存的对应密钥。

验证成功后才会加载配置和日志。遇到 401 / 403 时暂停管理请求和用量轮询，等待手动验证；403 会保留密钥。若 CPA 返回 IP 封锁及等待时间，页面会显示倒计时，到期后仍需手动验证。

备份和容器挂载需要覆盖以下位置：

| 位置 | 内容 |
| --- | --- |
| CPA 的 `auth-dir` | Cline Pass API key、账号优先级等凭据数据 |
| 插件数据目录，默认 `plugins/clinepassbridge-data` | 模型映射、设置、日志、统计和额度估计 |
| 插件目录，默认 `plugins` | 插件动态库 |

「重新分配会话」会让 CPA 清除本插件账号的旧绑定，后续请求按当前优先级重新选择账号，正在生成的回复继续完成。凭据恢复副本保存在 `auth-dir/.clinepassbridge-affinity-backups/`，其中包含密钥，随凭据目录一起保管。

## 模型与上游选择

插件只接受已配置的客户端模型名称。上游 ID 不会自动成为另一个可调用名称；需要直接用上游 ID 调用时，添加一条同名映射。升级会保留已有映射，删除或清空后也不会自动补回。

首次安装默认包含 `deepseek-v4.1-flash-1017` → `cline-pass/deepseek-v4.1-flash-1017` 映射，提供方允许列表默认填入 `deepseek`，能力默认使用 `vision,implicit-caching`。「获取上游模型」的候选列表直接读取 Cline 上游目录。1017 与老模型使用不同的上游 ID，已有用户需要自行勾选导入或手动添加映射。

模型通过 CPA 的账号绑定路径注册。所有 Cline Pass 账号禁用后，对应模型会从 CPA 的 `/v1/models` 移除；重新启用账号后，由 CPA 恢复注册。模型出现在列表中不代表上游请求一定成功，实际可用性仍受账号额度、冷却和上游状态影响。

在「钉上游」页可集中编辑各模型的 provider 允许列表：

- 留空：不限制提供方，由网关在符合能力条件的候选中路由。
- 只填一家：限制为该 provider；在应用允许列表的路由路径中，没有匹配的可用候选时请求会失败。
- 填多家：在应用允许列表的路由路径中，网关在列表内选择和回退。

上游策略在选择后自动保存；允许列表和能力条件在停止输入片刻、离开输入框或点击探测候选时自动保存。保存状态显示在对应区域右上角，失败时保留输入并提供重试；测试模型前会先完成保存。

DeepSeek 模型首次设置时默认填入 `deepseek`，其他模型保持自动路由。显式清空后不会再次自动填回。上游目前只对部分路由路径应用允许列表，仅填 `deepseek` 不保证从私有通道切到 DeepSeek；实际命中的 provider 以日志为准。

「探测可钉上游」会按已保存的能力条件发一个很小的模型请求，从返回的路由信息中读取候选。探测时保留最终的 `has`，移除顶层 `provider` 和 gateway 中的其他路由选项（包括 `only/order`），让现有提供方限制不影响候选列表。结果与凭据、模型和探测时段有关；空列表仅表示上游未列出候选，仍可手动填写并通过「测试模型」确认。

provider 策略默认是「插件配置优先」，客户端传入的路由条件会被忽略，由模型配置生成。选择「客户端优先」后，客户端传入的字段优先生效，缺少的字段由插件配置补齐。最终的 `only` 允许列表与 `order` 顺序提示会同时写入 `provider` 和 `providerOptions.gateway`，兼容读取不同路由字段的上游路径；`has` 只写入 `providerOptions.gateway`。

### 能力过滤（has）

`only` 限制提供方，`has` 按能力标签过滤候选。2026-10-23 对 `cline-pass/deepseek-v4.1-flash-1017` 的单账号实测中，仅 `only=[deepseek]` 仍落私有通道，仅 `has=[vision,implicit-caching]` 落到 `fireworks`，两者组合才得到 `finalProvider=deepseek`。指定 DeepSeek 时请一起设置；无后缀模型在该轮实验中仍落私有通道。完整七组对照和适用边界见[上游能力过滤](upstream-capability-filter.md)。

能力默认值按精确的上游 ID 判断，与客户端别名无关：

| 模型配置 | 默认值处理结果 |
| --- | --- |
| `upstream_id` 为 `cline-pass/deepseek-v4.1-flash-1017`，`has` 缺失或为 `null` | 补入 `["vision", "implicit-caching"]` |
| 同一上游 ID，`has: []` | 保持清空，不补默认值 |
| 任意模型，已有非空自定义 `has` | 保留自定义能力 |
| 其他上游 ID，`has` 缺失或为 `null` | 保持未配置 |

升级会让此前未配置能力的 1017 映射开始使用默认能力条件，已有提供方允许列表保持原值。想退出能力过滤，在界面清空后保存，或在模型配置中显式写 `"has": []`；下次加载也会保持清空。这是可覆盖的模型默认值，是否命中目标提供方仍需看实际路由。

每个模型都可在「钉上游」页自由编辑能力条件。1017 模型清空后想恢复组合，可点击「应用 DeepSeek 预设」：同时填入提供方 `deepseek` 和能力 `vision,implicit-caching`，随后自动保存；看到「已保存」再探测或测试。预设不修改模型 ID。也可以通过配置接口写入：

```json
{
  "models": [
    {
      "id": "deepseek-v4.1-flash-1017",
      "upstream_id": "cline-pass/deepseek-v4.1-flash-1017",
      "providers": ["deepseek"],
      "has": ["vision", "implicit-caching"]
    }
  ]
}
```

模型默认值处理后，再按 provider 策略合并客户端字段：

| 情况 | 上游请求里的 `has` |
| --- | --- |
| 配置了非空 `has`，客户端没带 | 用配置值 |
| 配置了非空 `has`，客户端也带了（策略为「客户端优先」） | 用客户端的值 |
| 配置了非空 `has`，客户端也带了（策略为「插件配置优先」） | 用配置值，客户端的被丢弃 |
| 处理默认值后仍无能力条件，策略为「插件配置优先」 | 不写该字段，客户端值也忽略 |
| 处理默认值后仍无能力条件，策略为「客户端优先」 | 保留客户端值；客户端也没带时不写 |
| 客户端显式带 `has: []` 或 `has: null`，策略为「客户端优先」 | 原样保留，不由配置或默认值补回 |

单个模型最多配置 8 个能力标签，保存时转小写、去首尾空白；配置接口要求字符串数组，重复项或标签内部含空白时会拒绝。模型配置的缺失值或 `null`（内部为 `nil`）表示采用该模型默认值，显式空数组 `[]` 表示关闭配置的能力条件；两者在保存和重载时保留各自含义。

判断是否命中目标提供方，看请求日志的「实际上游」列，对应上游回传的 `routing.finalProvider`。仅看 `canonicalSlug` 中的模型名称不足以区分提供方；指定 DeepSeek 时应确认最终值为 `deepseek`。

## 联网工具注入（server_tools）

「模型映射」每行右侧的「联网」按钮打开该模型的工具勾选：勾中的工具会在 bridge 构造上游请求体时追加到 `tools`，由上游网关执行（模型发起、上游检索、结果直接回灌给模型）。客户端不必自己声明搜索工具，也不会收到 `tool_calls` 或搜索结果原文。

可选的工具名由 Cline API 背后的 AI Gateway 提供：`vercel:exa_search`、`vercel:perplexity_search`、`vercel:parallel_search`、`vercel:tako_search`、`vercel:browserbase_search` 与 `vercel:browserbase_fetch`。界面上另有「其他类型」输入框，可用逗号写上游新增的名字；名字写错时上游返回 400，插件按普通上游错误处理。

存储格式仍是 `server_tools` 规则，因此也可以直接写进 YAML 或 `settings.json`；`models` 支持 `*` 通配：

```yaml
server_tools:
  - models: ["deepseek-v4.1-flash-*"]
    tools:
      - type: vercel:exa_search
      - type: vercel:tako_search
```

读取时插件把规则折算成每个已配置模型的实际工具集，所以通配规则写下的模型也会在界面上显示为已勾选。保存一个模型时会把整份视图重写成逐模型规则（`models: [<该模型 ID>]`）：手写的通配规则在这一步被展开成具体模型，已有且保留选中的工具仍保留完整参数，其他模型的工具定义也保持原样。清空勾选等于删除该模型的规则；清空全部工具后，重载也保留清空状态。

- `GET /v0/management/clinepassbridge/models/server-tools` 返回 `{"models":{<模型 ID>:[类型…]},"catalog":[…]}`
- `PUT /v0/management/clinepassbridge/models/server-tools` 提交 `{"model":"<模型 ID>","tools":["vercel:exa_search"]}`，只改这一个模型；未知模型返回 404，类型去重、空白忽略

注入只影响输入侧：客户端的 `tools` 原样保留，客户端已声明的同名工具不会重复追加。客户端函数与上述内建工具同名时（例如 `function.name: exa_search`），优先保留客户端函数并跳过对应的内建工具注入，避免上游名称冲突。规则不匹配的模型（例如 `mimo-v2.6-pro`）行为完全不变。搜索结果只进入模型上下文，客户端拿不到来源列表，需要可核验链接时用 `web_search` 类工具自行实现，或让模型在回答里复述 URL。

### 在请求日志中查看搜索调用

请求列表仅在上游回传正数成功调用次数时，在原模型请求上显示 `搜索 · Exa ×2` 等标记；多种工具共同使用时显示合计次数，悬停或展开可查看各工具次数、请求提供的搜索工具，以及每次上游尝试的记录。次数来自上游回传的成功调用计数，不根据模型回答或工具开关推断。

仅声明工具、上游未报告计数、明确回传空计数或 0，以及缺少计数字段的旧日志，列表和详情都不显示搜索信息或占位；日志元数据仍区分“未报告”和“明确报告 0”。流式重复报告按单次上游尝试保留各工具的最大累计值，不重复相加；不同尝试的已报告次数汇总到模型请求。有正数计数但部分尝试没有计数时，详情会标明汇总不完整。旧日志没有记录的字段不补算。

勾选“仅看搜索请求”只显示上游已报告正数调用次数的请求，对应 `GET /logs?network=used`。该筛选与状态、渠道、搜索及分页一起作用于请求日志；累计统计仍沿用原有独立口径。搜索词、结果正文、逐次搜索耗时和费用不在此功能中记录。

## 思考强度映射

在「模型映射 → 思考强度映射」选择模型，添加规则并保存。每个模型独立配置，默认关闭；多个别名即使指向同一上游，也有各自的规则。

只转换命中的规则，其他强度保留原值。删除规则后，该来源恢复透传；空规则表也全部透传。左侧来源不能重复，多个来源可以指向同一目标。

「未设置」在配置中记为 `unset`。例如「未设置 → max」可为未传强度的请求补值；目标选「未设置」则移除顶层 `reasoning_effort`，交给上游使用默认值。空字符串和 `null` 也视作未设置。请求已有顶层 `thinking` 或 `reasoning` 配置时，不额外补默认强度。

DeepSeek 模型会预填以下规则，但仍需要手动打开开关；其他模型预填空表。「恢复默认表」按上游 ID 判断是否为 DeepSeek。

| 请求传入 | DeepSeek 预填目标 |
| --- | --- |
| 未设置 | 未设置 |
| none | none |
| minimal、low | low |
| medium、high、xhigh | high |
| max、ultra | max |

配置写在对应模型的 `reasoning_mapping` 中：

```yaml
models:
  - id: deepseek-flash
    upstream_id: cline-pass/deepseek-v4.1-flash
    reasoning_mapping:
      enabled: true
      rules:
        unset: max
        medium: high
```

管理接口为 `PUT /v0/management/clinepassbridge/models/reasoning`，请求示例：

```json
{
  "model": "deepseek-flash",
  "upstream_id": "cline-pass/deepseek-v4.1-flash",
  "reasoning_mapping": {
    "enabled": true,
    "rules": {"medium": "high"}
  }
}
```

接口完整替换所选模型的映射，不合并旧规则。模型不存在时返回 404，上游 ID 已变化时返回 409，需要刷新后再保存。清空规则提交 `"rules": {}`。

旧版顶层 `reasoning_mapping` 会迁移到尚未单独配置的 DeepSeek 模型，已配置的模型保持原设置。新配置使用 `models[].reasoning_mapping`。

映射对正式请求、管理页模型测试和上游探测都生效，仅处理顶层 `reasoning_effort`，其他思考参数和 token 预算保持原样。命中规则时日志显示 `medium → high` 等转换记录，修改配置不会重写历史日志。

已核对的原版 CPA v8.0.13、v8.0.29 插件链路不应用全局 payload 规则。请在客户端显式发送 `reasoning_effort`，或使用插件的思考强度映射；管理页测试直接调用 Cline，不经过 CPA 全局 payload 规则。

## 统一错误规则

在「凭据管理 → 错误规则」统一添加、编辑、排序或删除规则，点击「保存并同步所有账号」生效。包含人工停用和额度暂停的账号，新账号自动使用这套规则。规则保存在插件数据目录的 `error-rules.json`，重启继续保留；同步失败会列出账号，点击「重试同步」重新应用已保存的规则。

每条规则同时指定状态码、动作和至少一个匹配条件。支持包含文本及 Go 正则表达式，同一规则任意条件命中即可，整张表从上往下采用首条匹配规则。默认规则按错误标识展示中文名称和原因，自定义规则展示状态码的通用说明；右上角「动作说明」可查看四种动作的区别。

| 动作 | 当前请求 | 后续调度 |
| --- | --- | --- |
| 停止 | 停止重试和切换凭据，返回错误 | 不因这条规则新增 CPA 冷却 |
| 停止并冷却 | 停止并返回错误 | 暂时排除失败的凭据或模型 |
| 继续 | 尝试后续模型或其他凭据 | 不因这条规则新增 CPA 冷却 |
| 继续并冷却 | 冷却失败对象并继续尝试 | 冷却期间跳过失败对象 |

停止不等于永久禁用，继续仍受可用候选和重试限制影响。表中行为以 CPA 实际收到的状态码和错误文本命中规则为前提。原版 CPA 的字符串流错误会丢失状态，调度匹配时可能视为无状态错误；对外默认封装为 500，也不代表匹配到了 500 规则。文案中的 `HTTP 502` 不会恢复规则匹配的状态。冷却时长由错误类型、上游 `Retry-After` 和 CPA 配置决定；插件自身的额度暂停与限流保护独立生效。

「恢复默认规则」只修改草稿，保存后恢复五条默认规则。清空规则并保存会清除所有插件账号的单凭据规则，由 CPA 使用适用的继承规则或默认错误处理。统一管理只作用于 ClinePassBridge 凭据，使用原版 CPA 的 `request_scoped_errors` 接口。已有凭据中的该字段继续保留，显式保存统一规则时按所保存规则更新；CPA 单凭据页面的修改可能被插件后续刷新覆盖。

管理 API 前缀为 `/v0/management/clinepassbridge`：`GET /error-rules` 查询当前规则、默认规则和同步结果；`PUT /error-rules` 接收 `{"rules":[...]}`；`POST /error-rules/sync` 接收 `{}`，重新同步；`POST /error-rules/reset` 接收 `{}`，直接恢复并同步默认规则。规则使用 `status`、`action`、`match`（文本数组）和 `match-regexr`（正则数组）。部分账号同步失败仍返回 200，通过 `sync.failed` 列出；统一配置保存失败返回错误并保留旧配置。

## 请求与模型测试

顶栏插件名右侧的小铃铛可查看公告，最新公告位于顶部，正文可独立向下滚动查看历史公告，标题和底部操作按钮保持可见。管理页成功读取插件版本后，首次自动弹出公告；关闭或前往配置概览后，刷新页面和升级插件都会保留关闭状态，仍可点击铃铛重新打开。只有发布时明确调整公告批次才会再次自动弹出。关闭状态按当前服务路径和公告批次保存在浏览器本地，换浏览器或清理站点数据后会再次提示；登录等弹窗打开时，自动公告会等待它们关闭。旧版按插件版本保存的关闭记录会自动沿用到初始公告批次。

维护公告时，普通发版或编辑公告内容保持 `internal/bridge/ui/index.html` 中 `releaseNoticeDialog` 的 `data-notice-revision` 不变；确实需要所有用户重新看到公告时，将它从 `1` 递增为 `2`，后续继续递增。该值独立于插件版本号，每个批次关闭一次后继续保持关闭。

请求超时新装默认 600 秒，可在「请求与日志设置」调整，范围为 10–1800 秒。升级保留已有值，旧设置为 180 秒时需要手动修改。

「配置概览 → 请求与日志设置」中的「最大响应大小 (MiB)」可调整响应上限，范围为 0.0625–64 MiB（1 MiB = 1,048,576 字节），转换后的字节数须为整数。配置字段 `max_response_bytes` 以字节整数保存，范围为 65,536–67,108,864；新装或旧配置缺少该字段时默认 64 MiB。已保存的值继续保留，旧用户原有 16 MiB 上限需要在此手动调整并保存。`PUT /v0/management/clinepassbridge/config` 支持单独提交该字段，例如 `{"max_response_bytes":67108864}`，其他设置保持原值；闲置截流开关仍默认关闭。

非流式模式可选：

| 模式 | 行为 |
| --- | --- |
| `stream-aggregate`（默认） | 直接请求上游 SSE，合并为 JSON 返回客户端 |
| `native` | 使用 Cline 原生非流式接口，解包 `success/data` |
| `native-fallback` | 原生响应出现空内容错误时，再尝试流式聚合 |

`native-fallback` 可能发起第二次上游请求。流式响应开始输出后不透明重试。完整输出在所有 choice 都结束、工具参数完整的情况下可兼容缺少 `[DONE]` 的 EOF；半截输出或传输错误仍会报错。

「配置概览」中设有独立的「重试兼容」栏目，位于「请求与日志设置」右侧。开关默认开启，点击圈 i 可查看用途，调整后点击「保存设置」生效。配置字段为 `client_retry_compatibility`（JSON / YAML 布尔值）；旧设置缺少该字段时默认开启，明确关闭后重启仍保持关闭。

开启时，指定 Fireworks/LiteLLM 响应截断使用 `HTTP 502: upstream response stream ended before completion: unexpected EOF (upstream_transport_incomplete)`；关闭时保留原始报错并补充 EOF 识别词。完整嵌套异常始终留在日志；规范文案可避免客户端被嵌套的 `TransferEncodingError: 400` 误导。

免新增冷却与此开关独立。插件按错误来源和结构化状态分类，对已归为请求范围的响应截断、闲置截流、网络/HTTP 回调失败、响应协议错误及上游 5xx，使用原版 CPA 的传输错误兼容路径，避免因本次故障新增账号/模型冷却。鉴权、402、429、套餐额度和团队限流优先保留原处置，包括被外层 502 包裹的明确受保护状态。该行为以插件实际分类和宿主识别为前提，不泛指所有 LiteLLM 错误或所有瞬时故障。CPA 与客户端分别按自身预算重试。详见 [兼容性说明](cpa-compatibility.md)。

已核对的原版 CPA v8.0.13、v8.0.29 流错误接口只传字符串。插件对上述已分类的请求故障使用 EOF/timeout 识别词或明确的 `[clinepassbridge:cpa_compat:...]` 标签，并在对应 RPC 错误中省略内部 `http_status`（0 表示缺失）；除下述 Chat Completions 兼容结构外，下游由 CPA 默认封装为 500，已开始的 HTTP 200 通过 SSE error 结束，插件日志保留内部状态。此类 RPC 故障不再匹配自定义的 500/502 状态规则。兼容标签仅用于宿主分类，不表示已经确认底层断流原因。

开启「重试兼容」时，原始请求路径为 `/v1/chat/completions`、已开始输出（`after_output`），且明确归为请求范围的 5xx、未命中显式规则或冷却/停止策略的流错误，使用单行 JSON：`error.type="server_error"`、`error.code="500"`。适用错误仅为 `upstream_service_error`，或内部网络子类型为 `eof` 的 `upstream_network_error`；EOF 依据传输错误类型、流完整性检查或已验证的结构化回调识别，不按报错文字猜测，其他网络故障沿用原编码。`message` 保留原兼容摘要和宿主分类标签。`500` 是供客户端识别的兼容业务码；已开始的 HTTP 200、日志原始状态/异常及 `error_details` 的真实 code/status 保持原语义。其他接口、缺少路径或关闭开关时沿用原编码。

该结构已用本机安装的 ZCode 3.16.2 解析与分类代码离线验证；客户端重试或回合恢复仍取决于输出/工具状态和自身预算，尚未完成整客户端交互验收。插件只编码错误，不新增上游请求或透明重放；上游故障仍以失败记录。

本地响应/帧/前导大小超限单列为 `response_limit_exceeded`（413），保留 RPC 的 413 状态，并在错误文本中携带 `invalid_request_error` JSON，供已核对的宿主按请求错误停止同请求轮换并跳过本次新增冷却；它与上述省略 RPC 状态的兼容路径不同。应排查输出大小或配置上限。取消、截止时间和插件关闭也按请求生命周期处理。插件不自动重放已输出的内容，也不清除已有冷却。

已核对的 DeepSeek Harness 外部 OpenAI compatible 路径（源码 `d743267388641bc76f17c45ce8b4c231aed1d32c`）按既有文案规则将该错误归为 `SERVER`。实际重试取决于是否启用 `llm-retry`、重试策略与预算；客户端版本或配置变化后以其实际行为为准。

独立网络路径保留网络、取消和截止时间的错误类型；原版 HTTP 回调缺少类型信息时按回调来源记为 `upstream_callback_error`，不据此断言 DNS、TLS 等具体原因。文本回调仅在错误全文或结尾精确匹配 `context canceled` / `context deadline exceeded` 时识别为 499 / 504。已收到的鉴权、额度、限流 HTTP 状态优先于读取正文时的网络失败。完整诊断保留在日志；受保护错误原文若含宿主传输识别词，对宿主使用受控摘要，避免反向误豁免。

模型测试使用所选凭据发送简短消息，固定流式聚合、`max_tokens: 64`，沿用超时设置，不自动重试或切换账号。可以选择思考强度；「未指定」默认省略字段，开启映射后按当前模型规则处理。模型支持哪些强度由上游决定，较强的思考可能增加耗时或耗尽输出预算。

测试会计入日志和统计。可展开查看错误详情，超出最大响应大小时标记截断。代理路径见 [调度与代理出口](scheduling.md#通用出口池实验性)。

## 流式卡住时提前截流

「配置概览」右侧「重试兼容」卡片下方设有独立区域，提供默认关闭的开关、数字秒数和圈 i 说明；点击该区域的「保存设置」独立保存。

| 配置字段（JSON / YAML） | 默认值 | 范围 |
| --- | --- | --- |
| `stream_idle_cutoff_enabled` | `false` | 布尔值 |
| `stream_idle_timeout_seconds` | `20` | 整数 1–1800 秒，关闭开关时也需有效 |

首次安装或旧配置缺少字段时使用对应默认值：开关关闭、阈值 20 秒。显式保存的 `true`、`false` 和自定义秒数（例如 10 秒、200 秒）升级及重启后继续保留，不会随默认值变化而改写；此前已保存开启的配置仍保持开启。`PUT /v0/management/clinepassbridge/config` 支持只提交这两个字段；与请求设置、重试兼容的独立保存互不覆盖。无效秒数返回 400，内存与已保存配置保持原值。例如，保存默认关闭、阈值 20 秒的设置：

```json
{"stream_idle_cutoff_enabled": false, "stream_idle_timeout_seconds": 20}
```

开启后，从首段有效输出后开始计时，后续思考、正文或工具增量均重置计时；heartbeat、role 和空帧不重置。默认 20 秒是连续缺少有效输出的空闲阈值，不缩短首字等待；首字等待与回复总时长仍由请求超时设置约束。关闭提前截流时，不因该空闲阈值结束请求，请求总超时仍生效。

向下游发送时暂停空闲预算，发送结束后继续剩余预算；不会把下游背压误算为上游无输出，也不会因一次元数据发送而重新获得完整等待窗口。请求总时长上限始终继续计时。非空的空格/换行仍按有效增量处理，本次修复不改变有效帧定义。

`debug`（JSON / YAML 布尔值）默认 `false`，旧配置缺少该字段时也关闭。通过 `PUT /v0/management/clinepassbridge/config` 部分更新 `{"debug":true}` 开启，提交 `{"debug":false}` 关闭，保存后重启保留。关闭时停止额外的流诊断采集，在途请求完成时也不写入 `stream_diagnostics`；闲置截流、核心错误、状态和用量照常记录。

开启 debug 后，新 SSE 请求日志的 `stream_diagnostics` 记录本次阈值、扣除下游发送后的空闲时间、最后读到上游字节/完整帧的时间、首末有效输出类型，以及下游发送累计/最长等待。仅记录时间、计数和固定类型标签，不记录对话、思考正文或工具参数。`last_upstream_byte_at` 是插件读回调返回数据的时间，不是网卡收包时间；旧日志没有这些字段，不倒推为零等待。

`GET /v0/management/clinepassbridge/logs` 顶层返回当前 `debug` 布尔值。关闭时所有返回项隐藏 `stream_diagnostics`，磁盘中的既有历史保留，再次开启后可显示；关闭期间完成的请求不补采诊断。

开启提前截流后，对所有上游 SSE 请求生效，包括向客户端流式输出、`stream-aggregate` 非流式聚合及 `native-fallback` 回退到 SSE 的阶段。`native` 原生非流式阶段不适用。它按实际输出空闲判断，不预知 LiteLLM 是否会失败。

原版 CPA v8.0.13 已提供 `host.http.stream_close`，v8.0.29 也沿用该接口，提前截流可独立使用。空闲达到阈值后主动结束上游，插件记录 `upstream_stream_idle_timeout`（内部状态 502）并结束失败请求。传给宿主的字符串流错误带 `i/o timeout`，通过已核对版本的文本兼容路径跳过本次新增账号/模型冷却，不依赖 CPA 补丁；已有冷却保持，且与「重试兼容」开关独立。首段输出前或非流式聚合经 RPC 返回该错误时省略内部 `http_status`，下游默认封装为 500；已开始的 HTTP 200 保持原状态，以错误帧结束流，不补正常完成帧。客户端按自身配置决定重试，实际冷却查看 CPA 状态。详见 [兼容性说明](cpa-compatibility.md)。

## 日志与统计

请求日志记录实际凭据、provider、思考强度、首字与总耗时、token 用量和输出速率。provider 来自上游响应或错误信息，未回报时显示「未知」；思考强度的 `—` 表示未识别到显式参数。

日志详情中的「实际服务模型」记录上游响应原始 `model`，独立于客户端模型别名与「实际上游」提供方。模型名匹配 `contributor-fallback(s)`、`/fallback(s)` 或 `-fallback(s)` 后缀时显示「降级池」徽章；该标记依据模型名称识别，缓存命中和首字耗时以本条日志为准。勾选「仅看降级池」可筛选这些请求，搜索也包含实际服务模型名。

日志 API 及每次上游尝试新增可选字段 `served_model`、`degraded`。`GET /logs?degraded=yes` 仅返回带降级标记的记录，`degraded=no` 返回未带标记的记录，省略或传 `all` 返回全部；筛选可与状态、提供方和搜索条件组合。旧日志缺少这些字段时仍可读取，「未报告」表示没有记录原始模型名。

响应截断单独显示为「响应截断」，空闲超时主动结束显示为「卡住截流」。展开日志可查看错误发生阶段、下游输出是否已开始、最后有效输出时间和有效输出帧数。`legacy_host_unknown` 表示宿主未确认结构化流错误支持；文本兼容没有宿主处理结果确认，保留该值仍合理，不表示识别词未生效，实际冷却需查看 CPA 状态。有效输出包括正文、推理及工具增量；首字时间表示插件收到此类增量，不等于最终客户端收到全部回答。

输入与输出用量各自保留是否被上游报告的标志。缺失值显示「未报告」，明确报告的零值显示 `0`；缺少完整用量的失败请求可能已经生成内容和产生消耗。统计继续使用实际报告的 token 数，不将缺失值估算成消费数据。

同一轮退避中的重复本地拦截合并为计数记录，真实上游限流和恢复探测独立记录。日志标注「本地退避」时没有调用上游。

统计独立持久化，可查看全部、今天、最近时段或自定义范围。按请求完成时间计入，不受日志条数上限或列表筛选影响。首次升级只导入仍保留的日志。

- 总 tokens 为输入加输出，缓存 tokens 已包含在输入中；缓存命中率为缓存输入除以总输入。
- 输出速率按输出 tokens 除以输出阶段耗时计算；缺少首字时间时使用总耗时。平均速率按有效样本的总输出除以总有效耗时计算，输出阶段不足 0.5 秒的请求不加入平均值。
- 「清空统计」切换统计代次，旧代次保留作恢复副本，请求日志、凭据和额度估计继续保留。

统计元数据在 `statistics.json`，分钟计数按 UTC 日期保存在 `statistics/<代次>/YYYY-MM-DD.json`。本地拦截不计消费和速率，合并计数约每两秒落盘，异常退出可能丢失末尾少量计数。

套餐用量是账号整体用量，额度金额是插件根据样本折算的参考值。计算方式见 [套餐用量说明](plan-usage.md#额度估计)。

## 上游限流

插件区分团队 token 限流、普通请求频率限制和套餐耗尽，分别记录为 `upstream_team_rate_limited`、`upstream_rate_limited` 和 `upstream_quota_exhausted`。

团队限流会按凭据和上游模型开启短期退避，同一上游的多个别名共享窗口。优先采用上游等待时间，缺失时等待 60 秒。窗口内直接返回限流，到期放行一次恢复探测；插件重载后重新探测。

团队限流错误带 `[clinepassbridge:team_tpm_limit]` 标识，供 CPA 请求级 `stop` 规则识别。该链路在 CPA v8.0.4 验证；普通 429、认证失败及套餐耗尽继续沿用宿主策略。通过原版 CPA 字符串流错误接口传递时按默认 500 封装，状态规则需以宿主实际收到的错误为准。

排查时可查看日志中的 `error_kind`、`retry_at`、`rate_limit_scope`、`upstream_skipped` 和 `stream_end`，区分上游限流、本地拦截与流中断。
