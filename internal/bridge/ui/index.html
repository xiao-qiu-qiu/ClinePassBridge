钉上游

为每个模型设置上游白名单，并选择插件配置与客户端参数的优先级。

  • 留空 = 自动路由。
  • 只列一个 = 强制固定到该上游；该上游满容量时整条请求会失败。
  • 列多个 = 白名单，网关会在白名单内自行回退；列出顺序仅为提示，不保证按序。
默认插件配置优先：忽略客户端的 providerOptions.gateway 与顶层 provider，不因此报错。客户端优先：客户端字段优先，配置列表只补齐客户端未提供的键。

模型上游白名单

使用逗号或空格分隔，也可点击探测到的渠道追加；留空恢复自动路由。可选上游需逐模型探测，结果取决于所用凭据；被分流到私有池的凭据不会返回候选。

批量探测按顺序使用开始时选中的凭据；结果仅保留在当前页面，不会自动修改白名单。

选择上游模型

勾选以添加，取消已有勾选以删除。仅同步名称与上游 ID 均匹配默认值的映射，自定义映射保持原样。

添加凭据

输入名称和 API Key。

数字越大越优先被调度；留空表示不设置，按 CPA 自身顺序。多个账号时，优先级高的会先被使用。

重新分配会话

CPA 会记住每段对话用过的账号，所以调高 2 号的优先级后，旧对话仍可能一直用 1 号。这里可以清除这些旧绑定，让后续请求按当前优先级重新选账号。

作用于本插件的所有会话，包括暂时没有发消息的对话。正在生成的回复会继续完成，从下一条请求开始重新选账号。
当前优先顺序

无需停用账号，也不用在操作期间发送消息。优先级相同时沿用 CPA 的调度策略；高优先级账号不可用时仍会选择其他账号。

清空全部统计？

将清空所有时段的累计请求数、tokens、速率和缓存统计，并从零开始累计。此操作不受当前统计时段限制。

请求日志、凭据和套餐额度保持不变。界面中不可恢复；服务端会保留重置前的备份。

采样依据与计价说明

钉上游：详细证据

以下均为 2026-10-03 的实测观测，上游风控策略可能随时变化。

证据

  • 账号差异：同一请求、套餐与额度上限完全一致的两个账号，行为相反。2 号：不钉 = deepseek，钉 deepseek = deepseek，钉无效 slug = 被上游拒绝；1 号：三种情况全部返回 openai-compatible-private。
  • 不是"账号本来就爱 deepseek"造成的假象：2 号钉 wafer / alibaba / fireworks / runware / novita，各自精确命中，而不钉时落 deepseek。
  • 模型差异：2 号 + deepseek-v4.1-flash 白名单强制执行；2 号 + glm-5.3 被忽略；kimi-k3（private/k3-contributor）与 glm-5.3-flash 没有公开候选。
  • 通道会变：1 号的账本显示它此前长期由公开网关服务（wafer 75、deepseek 54、fireworks 38 次…），之后才整体转为 openai-compatible-private。
  • 插件本身没有问题：隔离环境逐字节断言注入正确；把 only 传成字符串时上游会按字段名报 400，证明该字段确实送达网关。

时间线

  2. 10/2 16:52 起 — 发现经插件路径的 deepseek 全部转为 openai-compatible-private
  3. 10/3 02:30 — 双账号对比：2 号可钉，1 号三种请求全是私有通道
  4. 10/3 02:45 — 模型差异：glm-5.3 在 1号 和 2 号下均被忽略；kimi-k3 / glm-5.3-flash 无候选
  5. 10/3 02:55 — 2 号钉 wafer / alibaba / fireworks / runware / novita 全部精确命中
