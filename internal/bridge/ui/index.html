代理池使用指南

第一次用，从一条代理开始

  1. 点「添加出口」，填入一条能访问 Cline 的代理地址。先保留默认的每 60 秒 60 次、最大在飞 4 个，保存出口。
  2. 勾选「启用出口池」，点「保存策略」。用少量请求确认能正常回复，再逐步增加出口和流量。
  3. 遇到问题，可以关闭「启用出口池」并保存，恢复 CPA 原来的代理路径。已添加的出口会保留。

这些字段怎么填

启用出口池
总开关。开启后，没有独立代理的账号会轮流使用池内可用出口。请先添加出口；空池开启后，请求会排队并最终报“代理池无容量”。
排队上限
所有可选出口都忙时，最多等多久，范围 0–60 秒，默认 5 秒。有空位就马上发送；到时还没空位，返回本地 429。填 0 表示不排队。这不是每次请求固定等 5 秒。
名称
给自己看的备注，例如“东京出口 A”。方便区分即可，不影响调度。
代理地址
支持 HTTP、HTTPS、SOCKS5、SOCKS5H，例如 http://代理主机:端口 或 socks5h://用户名:密码@代理主机:端口。填 direct 表示直连。这里填的是 CPA 所在服务器能连接的地址；容器里的 127.0.0.1 指向容器自己。用户名或密码含 @、: 等特殊字符时需做 URL 编码。编辑已有出口时留空，会保留原地址和密码。
出口分组
同一个公网 IP 的代理填同一组，例如 tokyo-a，它们会共享请求数、并发和冷却。换端口或用户名不一定换了 IP。不同公网 IP 分开填；留空会创建独立分组。插件不会自动检测出口 IP。
每 60 秒请求数
这一组在最近 60 秒内最多发多少次请求，默认 60。时间窗口会向前滚动，不是每逢整分钟清零。用量查询、模型测试和实际发出的失败请求也计数；同组出口请填相同数值。
最大在飞请求
这一组同时最多有多少个尚未结束的请求，默认 4。流式回复没结束，就一直占一个位置。它和每分钟请求数是两回事；同组出口请填相同数值。
启用此出口
只控制当前这一条代理。取消勾选并保存后，后续请求会跳过它，配置仍保留。

看状态、排问题

“最近 60 秒”和“在飞”怎么看？

显示的是整个出口组的数据，所以同组的几条代理会显示相同数字，不要再把它们相加。页面约每 15 秒刷新一次，也可点「刷新状态」；很快结束的请求可能来不及显示在“在飞”里。

例如两个入口实际都是同一个 IP，各填 60 次、4 个在飞并归入同组，那么这一组总共还是 60 次、4 个在飞。只有确认是不同出口 IP，才适合分组单独计算。

报 429，是账号没额度还是代理忙？

“代理池无容量”表示本地暂时没有空位，这次还没发给 Cline。“出口 IP 限流”表示上游明确限制了该出口，整组会暂时冷却，默认 60 秒；上游给了等待时间时优先采用。

账号额度耗尽会暂停账号，团队限流另行处理。普通的未知 429 不会一律算成 IP 限流。具体是否继续尝试其他账号，还要看「凭据管理 → 错误规则」。

代理连不上，会自动换一条吗？

选出口时会跳过冷却或满载的组。但发出请求后连接失败，目前没有通用的自动换代理重发功能，也不会偷偷改成直连。先停用有问题的出口，再检查代理连通性。

目前没有自动测速、健康检查或故障节点自动淘汰。这里的默认数值只是插件的起始配置，不代表 Cline 承诺的容量。

Resin、订阅和账号独立代理怎么用？

Resin 按普通 HTTP 或 SOCKS 代理接入即可，其他代理服务也一样。这里逐条填写代理地址，暂不支持导入订阅或自动读取 Resin 节点列表；填一个网关地址，不会自动获得它内部所有节点的独立预算。

账号认证文件里的 proxy_url 独立代理优先于公共池。插件的凭据编辑弹窗目前还没有这个字段，需在 CPA 认证文件中配置。只想测试公共池轮询，就让账号独立代理留空。

独立代理未列入池时，按代理网关共享默认的 60 次、4 个在飞；想调整它的预算，可把相同代理地址添加到池中。该代理已在池里但被停用时，绑定它的账号不会自动改走其他出口。

重启或多台 CPA 共用代理时要注意什么？

代理配置会保存，重启后仍在；最近请求数和临时 IP 冷却保存在内存，重启后重新开始计算。保存配置时，同组已有的计数和冷却会保留。

多台 CPA 共用一个出口 IP 时，各台只统计自己的请求。请给各实例分配预算，别让每台都按整个 IP 的容量发送。代理池也不会增加账号套餐额度。

错误规则 · 动作说明

停止

当前请求：停止重试和切换凭据，将错误返回客户端。

后续调度：不因这条规则新增 CPA 冷却。

停止并冷却

当前请求：停止重试和切换凭据，将错误返回客户端。

后续调度：将失败的凭据或模型暂时排除出调度。

继续

当前请求：按 CPA 调度逻辑尝试后续模型或其他凭据。

后续调度：不因这条规则新增 CPA 冷却。

继续并冷却

当前请求：将失败对象冷却，再尝试其他可用候选。

后续调度：冷却期间跳过失败对象。

停止不等于永久禁用；继续仍受可用账号和重试限制影响。冷却时长由错误类型、上游 Retry-After 和 CPA 配置决定，不是延迟响应。插件自身的额度暂停与限流保护仍会生效。

输入名称和 API Key。

数字越大越优先被调度；留空表示不设置，按 CPA 自身顺序。多个账号时，优先级高的会先被使用。

重新分配会话

CPA 会记住每段对话用过的账号，所以调高 2 号的优先级后，旧对话仍可能一直用 1 号。这里可以清除这些旧绑定，让后续请求按当前优先级重新选账号。

作用于本插件的所有会话，包括暂时没有发消息的对话。正在生成的回复会继续完成，从下一条请求开始重新选账号。
当前优先顺序

无需停用账号，也不用在操作期间发送消息。优先级相同时沿用 CPA 的调度策略；高优先级账号不可用时仍会选择其他账号。

清空全部统计？

将清空所有时段的累计请求数、tokens、速率和缓存统计，并从零开始累计。此操作不受当前统计时段限制。

请求日志、凭据和套餐额度保持不变。界面中不可恢复；服务端会保留重置前的备份。

采样依据与计价说明

钉上游：详细证据

2026-10-23，同一测试账号、相同短文本的 7 次流式请求均正常结束。以下为网关报告的最终提供方。

  • DeepSeek 1017 默认 / 仅 only：均为 openai-compatible-private。
  • DeepSeek 1017 仅 has：为 fireworks，能力过滤本身不指定提供方。
  • DeepSeek 1017 only + has：连续 2 次为 deepseek；保留插件双字段格式再测 1 次，也为 deepseek，共 3/3。
  • 无 1017 后缀 + 同样的组合：仍为 openai-compatible-private。

组合为 only=[deepseek] 与 has=[vision, implicit-caching]，对应上游模型 cline-pass/deepseek-v4.1-flash-1017。当前版本会为尚未设置能力过滤的这类模型默认填入两项能力；自定义值和主动清空会保留。「应用 DeepSeek 预设」可恢复完整组合并自动保存。

判断以 provider_metadata.gateway.routing.finalProvider 为准：模型路径 deepseek/… 也可能由其他提供方服务。成功组合中的私有模型条目虽记为失败，但提供方尝试数为 0；本次只有一次实际提供方执行。

这些结果验证了该账号当时的请求路由，其他账号与后续时段请用「测试模型」复核。能力标签用于筛选，图片支持与缓存效果需按实际业务另行确认；响应成本字段也不等同于账号实际扣费。
